# AGENTS.md

Этот проект учебный.

Правила для Codex:

1. Писать простой и понятный код, доступный начинающему Go-разработчику.
2. `Lesson` является отдельной учебной сущностью.
3. В новом уроке сначала всегда показывать лекцию.
4. Вопросы должны относиться к конкретной лекции через `LessonID`.
5. Практика должна относиться к конкретной лекции и соответствовать её содержанию.
6. Новые термины объяснять до использования, а материал вести от простого к сложному.
7. Не показывать эталон до фиксации собственного ответа пользователя.
8. Не экспортировать эталонные ответы, полный текст лекции, подсказки или готовые решения.
9. Экспортировать только собственные ответы и практические результаты пользователя в UTF-8.
10. Не отправлять пользовательские результаты на сервер или во внешние сервисы.
11. Поддерживать обратную совместимость со старыми строковыми ответами в `localStorage`.
12. Не очищать результаты повторного прохождения без отдельного подтверждения пользователя.
13. Не использовать реальные персональные, рабочие или чувствительные данные.
14. Все примеры и тестовые данные должны быть нейтральными.
15. Не дублировать учебные данные в HTML или JavaScript: страницы получают их из приложения.
16. Для HTML-страниц использовать безопасный пакет `html/template` и не отключать автоматическое экранирование.
17. Сохранять интерфейс простым, читаемым и адаптивным.
18. Не удалять существующее JSON API без явного указания.
19. Не добавлять frontend-фреймворки, базу данных и другие внешние зависимости без явного указания.
20. После изменений выполнять:
    - `gofmt` для изменённых Go-файлов;
    - `go test ./...`.
21. Обновлять `README.md`, если меняется поведение проекта.
22. Новые уроки должны продолжать существующую последовательность без перенумерации уже сохранённых материалов.
23. Практическое задание не должно содержать готовое решение.
24. Примеры лекции не должны в совокупности образовывать полное решение практического задания.
25. Порядок обхода `map` нельзя описывать как гарантированный.
26. Поиск в `map` объяснять через конструкцию `value, ok`.
27. Объяснять, что результат `append` нужно сохранять в переменной slice.
28. Пользователь должен проверять успешный и ошибочный сценарии практического решения.
29. Экспорт должен сохранять полный фактический вывод пользователя без сокращения.
30. Нельзя сбрасывать предыдущие ответы или менять существующие ключи `localStorage` несовместимым способом.
